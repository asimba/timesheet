1. Общее описание системы

Система предназначена для учёта рабочего времени сотрудников: записи о выполненных работах привязываются к проектам (объектам) и группируются по отделам. Система работает как единый HTTP-сервис; данные хранятся в локальной SQLite-базе (base.db по умолчанию).

Основные сущности:

  • Группа (отдел) — верхний уровень группировки сотрудников.
  • Сотрудник — учётная запись с логином и паролем, привязанная к отделу.
  • Объект (проект) — работа, на которую сотрудники списывают время; имеет наименование и код (шифр).
  • Запись табеля — конкретная работа сотрудника на конкретном проекте: дата, время начала, длительность, комментарий.

Роли:

  • Администратор — управляет справочниками, сотрудниками, просматривает и редактирует табели любого сотрудника, делает экспорты, управляет резервными копиями.
  • Сотрудник — ведёт свои записи в табеле, видит только свои данные.

2. Файл конфигурации config.json

Приложение принимает путь к конфигурации через флаг -config. По умолчанию — config.json рядом с исполняемым файлом (или в текущем каталоге).

Пример:

{
  "listen_addr": "192.168.0.120",
  "listen_port": 8080,
  "admins": [
    { "user": "admin", "password": "secret" },
    { "user": "director", "password": "superpassword" }
  ],
  "db_path": "base.db",
  "log_file": "service.log",
  "work_entries_edit_days": 5,
  "backup_dir": "backups",
  "backup_interval_minutes": 30,
  "backup_keep": 7,
  "lock_file": "base.lock"
}
ПолеНазначениеПо умолчанию
listen_addrIP-адрес, на котором слушает сервер127.0.0.1
listen_portTCP-порт8080
adminsСписок администраторов (логин + пароль)обязательно хотя бы один
admin_user / admin_passwordАльтернатива списку (добавляется в admins)—
db_pathПуть к SQLite-базеbase.db
log_fileФайл журнала (пусто — журнал в stderr)—
work_entries_edit_daysСколько дней назад сотрудник может редактировать/удалять записи5
backup_dirКаталог для резервных копий (пусто — бэкапы отключены)—
backup_interval_minutesИнтервал резервного копирования в минутах60
backup_keepСколько последних копий хранить7
lock_fileФайл блокировки (защита от двойного запуска)<db_path>.lock
Пути (db_path, backup_dir, lock_file) могут быть относительными — они разрешаются относительно каталога, из которого запускается приложение. Относительные пути удобны, но при запуске через systemd или screen важно явно задавать рабочий каталог.
Пароли администраторов хранятся в config.json в открытом виде. Ограничьте права на файл (chmod 600 config.json) и не храните его в публичных репозиториях.

3. Первый запуск

  1. Убедитесь, что в config.json задан хотя бы один администратор.
  2. Запустите приложение: ./app -config config.json.
  3. При первом запуске будет создана база base.db и служебные таблицы.
  4. Откройте в браузере http://<listen_addr>:<listen_port>/.
  5. Войдите под учётной записью администратора — вы попадёте на страницу «Конфигурация».

Если в системе ещё нет ни одного отдела — в первую очередь создайте отдел (см. раздел «Группы и отделы»), иначе не получится добавить сотрудников.

4. Страница «Конфигурация»

Доступна только администратору. Содержит три вкладки:

  • Группы и отделы — управление отделами.
  • Сотрудники — управление учётными записями.
  • Объекты и проекты — справочник проектов.

На вкладках есть сортировка по столбцам (щёлкните по заголовку), пагинация (стрелки и номера страниц под таблицей) и кнопки добавления. Все изменения применяются сразу после сохранения в модальном окне.

5. Группы и отделы

Добавление

  1. Вкладка «Группы и отделы» → кнопка «Добавить группу/отдел».
  2. Введите наименование (до 200 символов).
  3. Сохраните.

Редактирование

В строке отдела нажмите карандаш. Наименование можно изменить в любой момент; на привязанных сотрудниках это не скажется.

Удаление

В строке отдела нажмите корзину и подтвердите. Удалить отдел, к которому привязаны сотрудники, нельзя — сначала переведите или удалите сотрудников.

Статистика по отделу

В строке отдела доступны две кнопки-пиктограммы:

  • Столбики — экспорт статистики по объектам, на которые списывал время этот отдел. Появится диалог с выбором: текущий месяц или все месяцы.
  • Столбики с человечками — экспорт статистики по сотрудникам отдела (суммарное время каждого сотрудника).

6. Объекты и проекты

Добавление

  1. Вкладка «Объекты и проекты» → кнопка «Добавить объект/проект».
  2. Заполните:
    • Наименование — до 1024 символов.
    • Кодовое обозначение (шифр) — до 20 символов, уникальное. Именно шифр сотрудники видят в выпадающем списке при добавлении записей.
  3. Сохраните.

Редактирование

В строке проекта нажмите карандаш. Шифр должен оставаться уникальным; смена шифра не затрагивает уже сохранённые записи табеля (они привязаны к ID проекта, а не к шифру).

Удаление

В строке проекта нажмите корзину. Удалить проект, на который есть ссылки из записей табеля, нельзя — сначала попросите сотрудников переписать часы на другой проект (или скорректируйте их табели сами).

7. Сотрудники

Добавление

  1. Вкладка «Сотрудники» → кнопка «Добавить сотрудника».
  2. При открытии диалога логин и пароль подставляются автоматически:
    • логин формируется как user<ID> (следующий ID в базе);
    • пароль генерируется из 8 символов.
  3. При необходимости отредактируйте поля вручную. Рядом с полем пароля есть кнопка-пиктограмма для генерации нового пароля.
  4. Заполните фамилию, имя (обязательно), отчество (опционально) и выберите отдел.
  5. Сохраните.
Логин и пароль передайте сотруднику удобным способом (например, устно или через корпоративную почту). Пароль хранится в виде bcrypt-хэша; посмотреть его из базы нельзя — только сгенерировать новый.

Редактирование

В строке сотрудника нажмите карандаш. Можно изменить ФИО, отдел и задать новый пароль (или сгенерировать его той же пиктограммой). Поле пароля отображается открытым текстом — это удобно для копирования и передачи сотруднику. Если оставить поле пустым — пароль не меняется.

Удаление

В строке сотрудника нажмите корзину. Все записи табеля удалённого сотрудника останутся в базе (они связаны с ним по ID), но привязка к учётной записи будет потеряна — восстановить вход этого сотрудника уже не получится. Если сотрудник увольняется, рекомендуется не удалять его, а сменить пароль, чтобы сохранить историю табеля.

Фильтр по отделу

Чтобы увидеть сотрудников конкретного отдела, откройте вкладку «Группы и отделы» и щёлкните по названию отдела — произойдёт переход на вкладку «Сотрудники» с фильтром по этому отделу. Под заголовком появится ссылка «сбросить».

Переход к табелю сотрудника

В строке сотрудника есть кнопки:

  • Табели (иконка календаря) — открыть табель сотрудника;
  • Статистика (иконка столбиков) — экспорт статистики по конкретному сотруднику.

8. Просмотр и редактирование табелей сотрудников

Администратор может просматривать и редактировать табели любого сотрудника без ограничения по давности записей (в отличие от самого сотрудника).

Открыть табель сотрудника

Из вкладки «Сотрудники» нажмите иконку календаря напротив нужного сотрудника. Откроется страница с его записями.

Добавить, изменить, удалить запись

Интерфейс тот же, что у сотрудника (см. пользовательское руководство), но доступны любые даты: администратора не ограничивает ни граница редактирования (work_entries_edit_days), ни ограничение «позже предыдущей записи».

Экспорт табеля сотрудника

На странице табеля нажмите «Экспорт в Excel» — выберите текущий месяц или все месяцы. Файл timesheet_<логин>_<месяц>.xlsx скачается в браузер.

9. Экспорт в Excel

Все выгрузки формируются в формате XLSX без дополнительных зависимостей. Содержимое по типам:

Что выгружаетсяГде кнопкаИмя файла

Табель сотрудника за все месяцыТам же → «Все месяцы»timesheet_<логин>_all.xlsx
Статистика по объектам отделаВкладка «Группы и отделы» → иконка «столбики» в строке отделаgroup_stats_<отдел>_<период>.xlsx
Статистика по сотрудникам отделаВкладка «Группы и отделы» → иконка «столбики с человечками»employees_stats_<отдел>_<период>.xlsx
Статистика по конкретному сотрудникуВкладка «Сотрудники» → иконка «столбики» в строке сотрудникаemployee_stats_<ФИО>_<период>.xlsx

В выгрузках по объектам присутствует колонка «Задействованные сотрудники» — перечень ФИО, работавших на проекте, каждое с новой строки. Длительности представлены в форматах ЧЧ:ММ и раб.дн. (8-часовые рабочие дни); для колонки «раб.дн.» в ячейках используются формулы, которые пересчитывают значение из колонки длительности в часах.

10. Резервное копирование

При заданном backup_dir приложение автоматически создаёт резервные копии базы:

  • один раз при старте (сразу);
  • затем каждые backup_interval_minutes минут.

Копия создаётся через VACUUM INTO — это штатный механизм SQLite, дающий консистентный снимок без остановки записи. Файл кладётся в backup_dir с именем <база>.<YYYYMMDD-HHMMSS>.bak.

Ротация: хранятся последние backup_keep копий, более старые удаляются автоматически. События (создание/удаление) пишутся в журнал (service.log).

Если backup_dir пуст — резервирование не запускается. Это удобно для тестовых запусков и разработки. На боевом сервере настоятельно рекомендуется включить резервирование.

11. Защита от двойного запуска

При старте приложение создаёт lock-файл (по умолчанию <db_path>.lock). Если файл уже существует — второй экземпляр не запустится и выведет содержимое lock-файла (PID, время старта, хост). Это защищает от случайного запуска второй копии поверх той же базы.

Штатное завершение

По Ctrl+C или kill -TERM lock-файл удаляется автоматически.

Аварийное завершение

При kill -9, падении, OOM lock-файл остаётся. Прежде чем удалять его, убедитесь, что процесс действительно не работает:

ps aux | grep app
# или на Linux:
pgrep -f './app'

Если процесс не найден — удалите lock-файл вручную:

rm base.lock
Если запустить второй экземпляр без удаления lock-файла — он завершится с ошибкой, но это безопаснее, чем два процесса на одной базе.

12. Журнал событий

Все события (запуск/остановка, ошибки БД, входы/выходы, изменения справочников и табелей, экспорты, резервное копирование) пишутся в файл log_file (например, service.log). Если log_file не задан — в stderr.

Примеры записей:

Сервер запущен: http://192.168.0.120:8080
[2026-11-06T10:00:00+03:00] lock-файл создан: base.lock (pid=12345)
[2026-11-06T10:00:00+03:00] резервирование БД: dir=backups interval=30m0s keep=7
[2026-11-06T10:00:01+03:00] резервная копия БД создана: backups/base.20261106-100001.bak (32768 байт)
[2026-11-06T10:12:34+03:00] пользователь: admin, действие: login, цель: session, результат: ok
[2026-11-06T10:15:22+03:00] пользователь: admin, действие: create, цель: employee(id=5, login="user5"), результат: ok
При необходимости ротации журнала используйте logrotate (приложение дописывает в файл, ничего не блокируя) или внешние средства сбора логов.

13. Восстановление из резервной копии

  1. Остановите приложение (Ctrl+C или kill -TERM); убедитесь, что lock-файл удалён.
  2. Сделайте копию текущей базы на случай отката: 
    cp base.db base.db.before-restore
  3. Выберите нужный файл из backup_dir, например backups/base.20261105-143000.bak, и замените на него текущую базу: 
    cp backups/base.20261105-143000.bak base.db
  4. Запустите приложение. Данные будут восстановлены на момент снятия копии.
Не выполняйте восстановление при запущенном приложении — можно повредить базу. Никогда не копируйте файл базы «на лету» (cp base.db … при работающем процессе): можно получить несогласованный снимок. Только через VACUUM INTO (это делает встроенный механизм резервирования) или при остановленном приложении.

14. Частые вопросы

Забыл пароль администратора — как восстановить?

Пароли администраторов хранятся в config.json в открытом виде. Откройте файл, замените пароль на новый, перезапустите приложение. Файл конфигурации читается только при старте.

Пользователь не может войти — как проверить?

Посмотрите service.log. При неудачном входе появится запись action=login result=fail reason=invalid_credentials (с указанием логина). Если логин в базе есть, но пароль не подходит — сгенерируйте новый через редактирование сотрудника. Если записи employee_not_found — логин введён неверно или сотрудник удалён.

Настройка «редактирование только за N дней» не работает для администратора

Так и задумано: администратор не ограничен этим лимитом. Ограничение действует только для сотрудников.

Куда делись старые резервные копии?

Хранятся только backup_keep последних. Если нужно хранить больше — увеличьте значение в config.json. Удалённые копии не восстанавливаются; при необходимости регулярно копируйте backup_dir в другое место (NAS, облако).

Почему при старте пишет «lock-файл уже существует»?

Прошлый экземпляр завершился аварийно. Убедитесь, что процесс не работает, и удалите lock-файл (см. раздел «Защита от двойного запуска»).

Что делать, если диск переполнен?

В первую очередь проверьте размер backup_dir — при большом числе копий и активной работе база растёт. Почистите старые копии вручную или уменьшите backup_keep и backup_interval_minutes (реже и меньше копий). Также проверьте log_file — при отсутствии ротации журнал может сильно разрастись.

Как перенести систему на другой сервер?

  1. Остановите приложение на старом сервере.
  2. Скопируйте config.json, base.db, при необходимости — service.log и последнюю резервную копию.
  3. На новом сервере положите файлы рядом с исполняемым файлом, поправьте listen_addr/listen_port при необходимости.
  4. Запустите приложение. Убедитесь, что создан lock-файл и нет ошибок в журнале.
Если нужна помощь по нестандартной ситуации — приложите к обращению фрагмент service.log с моментом проблемы и опишите, что именно делали.
